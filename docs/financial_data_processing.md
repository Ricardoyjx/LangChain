# 阶段一：金融数据处理与多模态索引构建

**核心目标**：将非结构化、多格式的金融文档转化为机器可理解、高可信度的结构化知识库。

## 1. 多源异构数据采集与清洗

### 1.1 数据源接入

对接上市公司公告（PDF）、券商研报（PDF/Word）、宏观经济指标（Excel/CSV）以及实时财经新闻（HTML）。

步骤一：识别与分发（代替 switch-case）
使用 pathlib 获取文件后缀，通过字典映射找到对应的解析器。
步骤二：专用解析（各显神通）
针对不同格式调用专门的库：
PDF：使用 pdfplumber（擅长提取表格和保留布局）或 PyPDF2。
Word (.docx)：使用 python-docx，可以提取段落、标题层级。
Excel/CSV：使用 pandas 或 openpyxl，将表格转化为结构化数据。
JSON/XML：使用 Python 内置的 json 和 xml 模块进行嵌套字段提取。

### 1.2 金融特有解析

针对金融文档中大量的财务报表、K线图、数据表格，引入专门的 OCR 与表格解析引擎，确保表格中的行列表头与数值能保持对应的语义关系，避免解析错乱。

### 1.3 数据清洗与脱敏

剔除研报中的免责声明、水印等噪音；对涉及非公开的内幕信息进行自动识别与脱敏处理。

## 2. 语义感知的金融文本分块

### 2.1 结构化分块

不按固定字符切分，而是基于文档的层级结构（如"1.1 营收分析"）进行切分，保证一个完整的财务分析段落不被打断。

### 2.2 元数据增强

为每个文本块自动打上多维度的金融标签，包括证券代码、报告期（如2025Q3）、行业分类、文档发布日期等，为后续精准过滤打下基础。

## 3. 双路索引与向量仓库构建

### 3.1 金融领域 Embedding

采用在金融语料上微调过的嵌入模型，确保模型能理解"净利润"与"归母净利润"等专业术语的语义差异。

### 3.2 双路存储

将带有丰富元数据的文本块同时存入向量数据库（用于语义理解）和搜索引擎（用于精确匹配股票代码、公司全称）。

## 阶段二：金融混合检索与合规后过滤

**核心目标**：在海量金融数据中，精准召回符合用户投资逻辑的片段，并严格把控合规与时效风险。

### 1. 金融场景混合检索

#### 1.1 双路并行召回

- **向量路**：理解用户的自然语言意图（如"分析一下比亚迪的护城河"）。
- **关键词路**：精准匹配具体的股票代码（如002594.SZ）、财务指标（如ROE、毛利率）。

#### 1.2 RRF融合

将两路结果进行倒数排名融合，确保既懂语义又能精准命中特定财务数据的文档排在前面。

### 2. 金融专属后过滤处理链

#### 2.1 基础去重

剔除同一份研报在不同渠道重复收录的冗余片段。

#### 2.2 时效性与版本过滤（核心）

金融数据对时间极度敏感。系统自动过滤掉过期的旧财报（例如用户问最新业绩时，自动屏蔽去年年报的数据），并优先保留最新发布的公告。

#### 2.3 权限与合规过滤（核心）

- **投顾资质校验**：识别用户角色，普通用户无法检索到"机构专属"或"高净值客户专享"的深度研报。
- **合规风控**：自动拦截包含"保本"、"稳赚不赔"等违规营销话术的文档片段，确保输出内容符合金融监管要求。

#### 2.4 金融 rerank 精排

使用金融垂直领域的重排序模型，对候选集进行深度语义打分，确保最贴合当前市场逻辑的资讯排在首位。

## 阶段三：智能投研结果输出与溯源

**核心目标**：生成专业、客观且可验证的金融分析结论，杜绝大模型"一本正经地胡说八道"。

### 1. 动态提示词组装

#### 1.1 上下文注入

将经过严格过滤和精排的 Top-K 个金融片段（如最新的营收数据、分析师观点）填入提示词模板。

#### 1.2 思维链引导

在提示词中引导模型按照"核心观点 -> 数据支撑 -> 风险提示"的金融研报逻辑进行作答。

### 2. 大模型生成与数值校验

#### 2.1 客观回答生成

大模型基于检索到的真实数据生成回答，严禁模型使用训练数据中的过时记忆来回答实时行情问题。

#### 2.2 数值一致性检查

在输出前，增加一道校验工序，确保模型生成的数字（如"营收增长15%"）与检索到的原文数据完全一致，防止计算幻觉。

### 3. 引用溯源与原文链接

#### 3.1 精准溯源

在回答的每一句关键结论后，自动标注引用来源（如：[1] 中信证券-比亚迪深度研报-2025/05/18）。

#### 3.2 原文跳转

提供原文链接或 PDF 页码跳转功能，方便专业投资者快速核对原始凭证，建立对系统的信任感。
